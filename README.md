# DraftRelay · 离线草稿同步演练台

针对展会现场弱网改稿的真实事故（断网连续编辑 + 第二个标签页 + 恢复网络后旧草稿覆盖新内容、界面却显示「已同步」）而做的可复现演练台。页面内模拟 **两台客户端、离线操作队列、服务端确认与重连**，所有行为确定可回放。

## 运行

```bash
npm install
npm run dev      # 开发
npm test         # 全部测试（25 个）
npm run build    # 类型检查 + 生产构建
```

## 演练内容

- **分块编辑**：每个块可更新 / 删除 / 上移下移 / 插入，全部以操作（Op）形式进入队列
- **因果关系**：每条操作携带 `opId`、逻辑时钟、`baseVersion`（基于哪个服务端版本产生），时间线完整展示 操作 → 送达 → 应用 → 广播 → 确认 的因果链
- **待确认状态**：队列区分「待发送 / 待确认·尝试次数」，并预演每条操作重放后的结局（将被丢弃 / 将被覆盖）
- **服务端版本与合并来源**：服务端面板展示权威版本、每个块的最终来源（哪条操作胜出）、冲突仲裁记录
- **关键保证**：
  - 迟到确认（版本更小）一律忽略，**不回退**
  - 重复确认 / 重复重试按 `opId` 幂等去重，**不二次推进**
  - 冲突规则：删除优先；更新/移动按 (逻辑时钟, 客户端ID) 较大者胜，与到达顺序无关
  - 「已同步」只在待确认队列真正为空时成立

## 控制

单步 / 自动播放 / 暂停 / 撤销 / 重做 / 重置；网络面板可断链、对任意在途消息注入 **丢弃 / 延迟 / 复制 / 乱序** 故障、手动重试、以及注入「旧快照回灌」复现线上 bug。状态自动保存到 localStorage，**刷新页面自动恢复**。

## 预排场景

| 场景 | 演示点 |
| --- | --- |
| 乱序确认与迟到确认 | 版本跳跃前进、迟到确认忽略 |
| 双端离线冲突与合并来源 | 并发改同一块、改 vs 删、三方收敛 |
| 重连冲刷与重复重试 | 队列因果序冲刷、服务端幂等（v3 而非 v6） |
| 旧快照回灌 | 线上 bug 复现：待确认被吞、假「已同步」 |
| 自由演练 | 无脚本，随意组合 |

## 结构

```
src/sim/      确定性模拟内核（纯数据、无随机无时钟：可撤销、可持久化、可重放）
  types.ts      类型
  doc.ts        操作应用与冲突规则（服务端/客户端共用）
  server.ts     服务端：幂等去重 + 仲裁 + 广播
  client.ts     客户端：乐观草稿 + 待确认队列 + 确认处理
  network.ts    在途消息 + 故障注入
  sim.ts        世界状态与动作归约
  scenarios.ts  预排演练脚本
src/store/    撤销/重做历史 + localStorage 持久化
src/ui/       React 面板
tests/        vitest：乱序确认、双端冲突、重连、重复演练、撤销重做、持久化、UI 冒烟
```
