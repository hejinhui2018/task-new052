# DraftRelay · 离线草稿同步演练台

模拟“展会现场弱网改发布说明”的故障场景：两台客户端、一个服务端、可注入故障的网络。
用来演练和验证离线编辑队列、重连追赶、冲突合并与幂等确认的正确性 ——
特别是“旧草稿覆盖新内容，界面却显示已同步”这类问题：本演练台的状态徽标是**诚实的**，
只有在「待确认队列为空 且 本地已并入服务端最新版本」时才显示 `已同步 ✓`。

## 运行

```bash
npm install
npm run dev      # 开发服务器
npm test         # 引擎测试（vitest）
npm run build    # 生产构建
npm run typecheck
```

## 怎么演练

1. 顶栏选择预置脚本（双端冲突 / 迟到确认与重复重试 / 离线队列 / 乱序确认），点「运行脚本」自动播放；
   或用「单步」一拍一拍观察。
2. 也可以完全手动：直接在任一客户端编辑块文本（回车/失焦提交）、↑↓ 移动、＋插入、✕删除；
   用「断开网络」进入离线，操作会进入待确认队列；恢复网络后自动握手追赶并冲刷队列。
3. 在中间「网络」面板注入故障：丢弃 / 复制 / 延迟 / 乱序下一条消息，或开启混沌模式。
4. 「撤销 / 重做」是整台模拟的时间旅行；页面状态持久化在 localStorage，刷新可从断点恢复；「重置」清空。

## 界面读法

- **客户端面板**：本地视图（乐观生效）、每块的来源徽标（A/B/初始·版本）、待确认队列（发送次数、冲突重基提示）。
- **服务端面板**：权威版本号、每块的最终合并来源、版本日志（每条记录 `基于 vX → vY` 的因果链与 `⚠覆盖` 关系）、乱序缓存。
- **网络面板**：在途消息、链路状态、故障注入、统计（重试/拒重/忽略等）。
- **事件时间线**：每一次状态推进的因果记录，可按「操作与确认 / 网络与故障 / 冲突与忽略」过滤。

## 正确性机制（被测试覆盖）

- **幂等**：操作带全局唯一 `opId`，服务端去重，重复重试不推进版本；客户端按版本号忽略迟到/重复确认。
- **因果顺序**：操作带客户端内序号，服务端对乱序到达的操作先缓存、前驱补齐后再应用。
- **冲突合并**：同一块的并发修改按服务端到达顺序生效（最后写入者胜出），日志记录 `覆盖 谁@哪个版本`，
  每个块的最终来源（`blockMeta`）在界面上可见；被覆盖方会收到明确的冲突事件，而不是静默丢字。
- **诚实状态**：见上。

## 结构

```
src/engine/    纯函数状态机（无 React 依赖，可单测）
  types.ts       状态与消息类型（整体可 JSON 序列化）
  core.ts        块操作应用、客户端视图、同步状态等纯函数
  sim.ts         归约器：tick 推进、收发、服务端幂等/乱序缓存、客户端重基
  scenarios.ts   预置演练脚本
  persistence.ts localStorage 持久化
  sim.test.ts    乱序确认 / 双端冲突 / 重连 / 幂等 / 重复演练 / 刷新恢复 等测试
src/store.ts     React 状态仓库：dispatch、撤销/重做、自动播放、持久化
src/components/  界面（顶栏、客户端、网络+服务端、时间线）
```
